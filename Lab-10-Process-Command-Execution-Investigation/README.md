# Lab 10 — Process & Command Execution Investigation

## Objective

Investigate process and command execution activity on a Kali Linux endpoint using Wazuh.

The objective of this lab is to demonstrate how a SOC Analyst can identify:

- Which user executed a command
- Which command was executed
- Whether the command was executed with root privileges
- The endpoint involved
- The log source and decoder
- The Wazuh detection rule
- The relevant MITRE ATT&CK technique
- Whether the activity is suspicious or legitimate

## Scenario

A SOC analyst needs to investigate command execution on a Linux endpoint.

A controlled command was executed using sudo to simulate privileged command execution.

The activity was then investigated through the Wazuh Dashboard.

## Step 1 — Verify Wazuh Agent

The Wazuh agent service was verified as running on Kali Linux.

sudo systemctl status wazuh-agent --no-pager

The agent was active and communicating with the Wazuh Server.

## Step 2 — Verify Journald Collection

The Wazuh agent configuration was checked to confirm that systemd journal logs were being collected.

<localfile>
  <log_format>journald</log_format>
  <location>journald</location>
</localfile>

This allows Wazuh to collect Linux systemd journal events.

## Step 3 — Generate Controlled Command Execution

A harmless command was executed using sudo:

sudo touch /tmp/lab10-command-execution-test

The command created a temporary test file.

The Linux journal recorded the execution:

USER=root ; COMMAND=/usr/bin/touch /tmp/lab10-command-execution-test
## Step 4 — Wazuh Detection

Wazuh detected the sudo command execution.

The alert generated by Wazuh was:

Rule ID: 5402
Level: 3
Description: Successful sudo to ROOT executed.

The event was collected from:

Location: journald
Decoder: sudo
## Step 5 — Wazuh Alert Investigation

The Wazuh Dashboard event showed:

Agent: kali-soc-lab
Agent IP: 192.168.158.3

Source User: sai
Destination User: root

Command:
/usr/bin/touch /tmp/lab10-command-execution-test

Working Directory:
/home/sai

TTY:
pts/0

Decoder:
sudo

Rule:
5402

Level:
3

The event demonstrated that the user sai executed the command with root privileges.

## Step 6 — Process Investigation

A second controlled command was executed to demonstrate command execution and system information gathering:

sudo bash -c 'id; whoami; uname -a'

The command returned:

uid=0(root) gid=0(root) groups=0(root)
root
Linux vbox 6.18.5+kali-amd64 ...

This confirmed that the command executed with root privileges.

Wazuh captured the command:

/usr/bin/bash -c 'id; whoami; uname -a'

The event was again detected by:

Rule ID: 5402
Level: 3
Description: Successful sudo to ROOT executed.

## The command itself was intentionally executed as part of this controlled lab.

Therefore, the activity was classified as legitimate test activity rather than a real compromise.

## MITRE ATT&CK Mapping

T1548.003 — Sudo and Sudo Caching

Wazuh mapped Rule 5402 to:

T1548.003
Sudo and Sudo Caching

This technique is associated with abuse of sudo or sudo-related mechanisms to execute commands with elevated privileges.

## SOC L1 Investigation

A SOC Analyst investigating this alert should examine:

1. User

Identify the account that executed the command.

sai
2. Privilege

Determine whether the command was executed with elevated privileges.

root
3. Command

Identify exactly what was executed.

/usr/bin/touch /tmp/lab10-command-execution-test

and:

/usr/bin/bash -c 'id; whoami; uname -a'
4. Endpoint

Identify the affected endpoint.

kali-soc-lab
192.168.158.3
5. Timestamp

Review when the command occurred and correlate it with other events.

6. User Intent

Determine whether the activity was:

Authorized administrative activity
Security testing
Automated activity
Potential privilege abuse
7. Correlation

Check surrounding events for:

Authentication activity
Failed logins
Other sudo commands
Account changes
Persistence activity
Network activity
File modifications

## Key Takeaways

This lab demonstrated how Wazuh can monitor Linux command execution performed through sudo.

A SOC Analyst can use the captured command, user, privilege level, endpoint, timestamp, decoder, and MITRE mapping to investigate whether privileged command execution is legitimate or potentially suspicious.

The lab also demonstrated the importance of investigating the actual command rather than relying only on the alert description.
